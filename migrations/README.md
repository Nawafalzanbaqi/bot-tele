# Migrations

Alembic owns the PostgreSQL schema. The in-memory backend needs none of this.

## Commands

```bash
make migrate                       # apply everything pending
make migration m="add tags table"  # autogenerate from model changes
docker compose exec api alembic downgrade -1
docker compose exec api alembic history --verbose
docker compose exec api alembic upgrade head --sql   # review SQL without applying
```

The API container applies migrations on start when
`MEDIAHUB_RUN_MIGRATIONS=true`.

## Rules

1. **Review every autogenerated migration.** Alembic diffs metadata against the
   live schema; it guesses at renames and cannot see data.
2. **Never edit a migration that has been applied anywhere.** Add a new one.
3. **Write the downgrade.** An upgrade you cannot reverse is an outage waiting
   for a bad deploy.
4. **Separate schema changes from data backfills.** A long backfill inside a
   DDL transaction holds locks for its entire duration.
5. **Additive first.** Add a nullable column, backfill, then add the
   constraint - three deploys, zero downtime.
